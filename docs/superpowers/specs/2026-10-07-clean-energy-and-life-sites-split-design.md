# 清洁能源、化工与生活观察双网站拆分设计

## 目标

把现有的个人观察站拆为两个内容、资料文件、自动更新和公开网址均独立的 GitHub Pages 网站：

1. 保留现有仓库与网址，改名为“清洁的能源、化工信息网”。它只发布绿色燃料、氢能、沼气、绿色化工与碳交易的信息。
2. 新建“我的生活：财经、AI与风景”。它只发布全球股市、大宗商品、人工智能、风景与文化、时光宝盒和家人授权入口。

两个网站不共享运行时脚本、`weekly-intelligence.json`、GitHub Actions 工作流或图片目录。它们可以在页脚以普通外部链接互相推荐，但任一网站均可独立运行与更新。

| 默认语言 | 简体中文，保留现有英文资料字段 | 简体中文，保留现有英文资料字段 |

新仓库采用小写英文连字符作为 URL 路径，以避免中文路径编码和将来维护问题；页面上始终显示用户指定的中文名称。

## 数据与自动更新边界

现有 `data/weekly-intelligence.json` 的主题按 ID 拆分，任何主题只能存在于其中一个网站：

| 网站 | `topics` ID |
| --- | --- |
| 清洁的能源、化工信息网 | `methanol`, `saf`, `ammonia`, `hydrogen`, `biogas`, `carbon` |
| 我的生活：财经、AI与风景 | `stocks`, `commodities`, `ai`, `scenery` |

每个站保留自己的 `scripts/update-weekly-intelligence.mjs` 和 `.github/workflows/weekly-intelligence.yml`。两个工作流均在每周一运行，但只抓取本站的数据文件中存在的主题；每个主题最多保留三条信息。每条卡片必须始终显示：主题、发布日期、来源名称以及可点击、非空的“查看原文”链接。

私密内容不会进入 JSON，也不会由自动任务抓取。家人授权版仍只是公开的授权说明与入口，不实现登录或上传功能。

## 页面与代码结构

### 清洁能源网站

- `index.html`：清洁能源、化工与碳交易的站点首页。
- `intelligence.html`：绿色燃料、氢能与沼气、碳交易观察，以及全球清洁能源与碳资源台。
- `framework.html`：能源与化工观察框架，只保留能源转型内容。
- `style.css`、`script.js`：删去财经、AI、风景、记忆的渲染分支和导航链接。
- `assets/`：仅留下该站实际使用的站点视觉资产；迁出的时光宝盒图片不再由此站引用。

### 生活网站

- `index.html`：财经与 AI、时光宝盒、长期观察框架的站点首页。
- `intelligence.html`：国际主要股市、国际主要大宗商品市场、人工智能动向和对应的资源台。
- `memories.html`、`family.html`：从原站完整迁入，并保持现有的公开/授权边界。
- `framework.html`：资本趋势、风景与文化、人工智能动向三个模块；不含能源转型。
- `assets/`：迁入时光宝盒、风景与文化所需的图片和新站所引用的视觉资源。
- `data/`、`scripts/`、`.github/workflows/`：为新仓库复制的独立版本，只含生活网站的四类主题。

每一页使用本站相对路径链接；跨站入口若保留，使用完整 HTTPS URL，并带有“前往清洁能源、化工信息网”或“前往我的生活：财经、AI与风景”的清楚说明。

## 错误处理与隐私规则

- 更新脚本抓取失败时，保留该主题的上一次有效条目，不能写入空链接或占位来源。
- 浏览器渲染时忽略没有有效 `http`/`https` URL 的条目；页面显示简短的“等待可靠来源更新”提示，而不是无效按钮。
- 两站的数据、图片和 HTML 中都不包含真实邮箱、家庭私密影像、精确私密地点或需要授权的内容。
- 新站的“家人授权版”不得被自动更新脚本引用。

## 验收标准

1. 两个 Pages 网址均可打开，各自显示指定的中文站名和本站导航。
2. 清洁能源网站不含 `stocks`、`commodities`、`ai`、`scenery` 主题或时光宝盒/家人授权页面链接。
3. 生活网站不含 `methanol`、`saf`、`ammonia`、`hydrogen`、`biogas`、`carbon` 主题或绿色能源情报页面链接。
4. 新旧两个 JSON 文件的主题 ID 并集等于原始九个主题、交集为空。
5. 两个更新脚本都通过现有的链接完整性和每主题最多三条信息测试；新增的拆分测试验证上述互斥性。
6. GitHub Actions 的手动运行各自只提交本仓库的数据更新；不得跨仓库写入。
7. GitHub Pages 配置为各仓库的 `main` 分支根目录，发布后用实际公网 URL 检查标题、导航、筛选和“查看原文”链接。

## 不在本次范围

- 用户登录、身份认证或真实的家人授权系统。
- 私人照片、视频或家庭档案的上传。
- 新增第三方数据服务、付费 API 或额外域名。
- 更改内容本身的新闻立场或人工撰写新的新闻摘要；本次仅按既有主题和来源划分。
